LOOPS
LOOP	CADENCE	WHAT IT CHECKS	IF IT FAILS	FOREMAN ADDS
Cycle	per task	Take the first task in the queue, build it, run the hard checks, run a read-only review, keep or undo.	Undo, keep a patch as failure evidence, task goes to failed.	A lease and fencing token per task, so two runners never take the same one.
Runner poll	every 15 seconds	Codex process alive, time box not passed, console and status refreshed. Dashboard data refreshed at least every 5 minutes.	Past the time box: stop the whole process tree and undo.	Heartbeat file written by the runner, so liveness is a fact, not a guess.
Watchdog	every 15 minutes	Heartbeat age, log growth or files changed, elapsed against time box and estimate, idle worker while work is ready, queue depth, reviewer last run.	Nudge, then restart the runner through the .cmd loop, then escalate.	Adaptive thresholds: warn at 2x the estimate, escalate at 4x, never silent.
Allowance retry	every 15 minutes	Codex usage allowance. The refill time Codex reports is shown, not waited for.	Wait and keep checking. Other lanes continue.	Same rule per provider, with fallback to another provider for the role.
Test cap	10 minutes	Test run finishes. A test stuck on a dialog can never freeze the runner.	Stop the tests and send the hang back as a repair instruction.	Per-project cap set in harness.yaml.
Reviewer	scheduled; nightly deep review	Review every kept and undone task, keep at least 5 tasks queued, record decisions, turn repeated mistakes into checks.	After 3 failures, park the task with a short diagnosis.	Catch-up cursor: last reviewed commit, so nothing is skipped.
Standalone planner	queue empty	Codex plans 1 to 3 small tasks from the plan, through the same checks and review.	3 undone in a row: pause 1 hour. 5 tiny in a row: pause 30 minutes, plan larger batches.	Never touches money rules, plan changes or owner decisions.
Self-update	between tasks	New launcher or guide files wait in the mailbox, get installed and committed, and the runner reloads itself.	A bad update falls back to the last good launcher.	Same mechanism for every project's harness files.
THE MARKDOWN MAILBOX
inbox\	Claude writes new tasks here while Codex is busy. The runner moves them into the queue between tasks.
inbox\files\<path>	New versions of tracked files (launcher, plan, guides). Installed and committed between tasks.
queue\ done\ failed\	One task file per task; names sort in execution order.
results\	Codex result and the review verdict for each task, as JSON.
BUSY.txt	Exists while Codex works. Claude touches only the inbox and dashboard data meanwhile.
claude-reviewed.txt	Last commit Claude reviewed, for catch-up.

Foreman adds a sequence number and an acknowledgement file to every message, and writes each file to a temporary name first, then renames it, so a half-written task is never picked up.

Every Done-when line must be checkable from Codex’s sandbox. Visual, desktop and network checks go in the Claude checks line.

HARD CHECKS AFTER EVERY BUILD
check	Only the Allowed paths changed
check	No protected file changed
check	Under the line limit; no file over 400 lines
check	No forbidden machinery added
check	Nothing written under state\
check	Codex made no commit itself
check	Result status is done
check	Tests pass, with a 10 minute cap
ESCALATION LADDER

Try differently, then park the item and move on, then change the lever (instruction revision, stronger model, another tool). Work continues the whole time.

The owner hears only about money, kill criteria, product changes he would notice, credentials, and an unreachable machine for 2 hours. Claude never writes deliverables, only tasks, reviews and decisions.
